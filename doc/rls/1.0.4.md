# Release 1.0.4 - Changelog Summary

This release turns Vibe4Dock into a fully browser-driven AI workspace: the new Chat addon puts a ChatGPT-like web UI in front of a headless OpenCode agent working directly on the project, and path-based routing makes every browser endpoint reachable through a single port. The release also polishes the dashboard, hardens the rebuild flow, and clarifies how credentials are configured across base services and addons.

- **Chat Addon (AI Assistants category)**
  New `chat` addon exposing a ChatGPT-like web UI in front of a headless `opencode serve` instance working on the mounted project directory.
  Shell activity is shown in a collapsible thinking panel; agent questions and permission requests appear as interactive bubbles.
  Includes model selection, slash commands, command execution, a file upload API, and session navigation.
  The chat declares `opencode-cli` as a hard dependency: install the OpenCode CLI tool first - no other agent backend is supported.

- **Chat Authentication and Credentials**
  HTTP Basic Auth for the chat UI is optional and configured through the Addons section of the tools UI (`CHAT_USERNAME` / `CHAT_PASSWORD`).
  These values live in the `chat` service environment of the generated `docker-compose.override.yml`, not in `.env.local`.
  Without credentials the chat UI is accessible without authentication, like the shells; as soon as both values are set, HTTP Basic Auth is enabled.
  Documentation (English and German READMEs, generated project README, and the addon help texts) now describes this split between `.env.local` (tools UI and shells) and addon settings (chat).

- **Path-Based Routing Mode**
  Projects can now choose between `ports` routing (each endpoint on its own host port) and `paths` routing (a single HTTP port serving everything through a built-in nginx proxy under reserved `<prefix>-*` paths).
  The base path prefix is configurable, and path-capable addons dock in automatically while non-HTTP addons keep their own ports.

- **Rebuild Flow Hardening**
  `rebuild.sh` now rebuilds every service image instead of only `web`, and the rebuild handling plus upload API in the tools UI were extended.
  The chat nginx config sends `Cache-Control: no-cache` headers so UI assets always stay fresh after rebuilds.

- **Default PHP Version 8.5**
  New projects are generated with PHP 8.5 by default.

- **Web Container Fix**
  The webdevops entrypoint no longer loses the `suid` bit on `gosu`, fixing `docker compose restart web` issues.

- **UI Polish**
  Modern thin scrollbar styling for dashboard and browser shells, clean browser tab titles, and an OpenCode CLI tool id fix that removes the collision with the opencode addon.

- **Version Bump and Documentation**
  `src/Cli.php`, `README.md`, and `readme/README.de.md` were updated to reflect the 1.0.4 release, and `doc/rls/1.0.4.md` was added.

**Compatibility**: Backward compatible. Existing projects keep working; the chat addon is opt-in and only installable when the bundled `opencode-cli` tool is installed.
