# Release 1.0.6 - Changelog Summary

This release replaces the browser basic-auth prompt for path-routed shells and the chat with a proper form login backed by signed session cookies served through the proxy, propagates tool mounts into the compose services of addons that depend on the tool, and polishes the chat model selection labels.

- **Cookie-Based Authentication and Form Login (Proxy + Web)**
  Path-routed tools and addons (application shell, root shell, chat) are no longer protected by the browser's basic-auth dialog but by a form login page served through the proxy by the web container.
  The proxy now performs an `auth_request` subrequest to `/vibe-auth/index.php?action=check&service=<slug>`; on a 401 response the browser is redirected to the realm-free form login at `/vibe-auth/?service=<slug>&back=<path>`, which is browser-cache friendly.
  A successful login sets an HMAC-signed session cookie (`vibe_<slug>_auth`) with a 30-day TTL - one cookie per service.
  The new endpoint lives in `skeleton/public/vibe-auth/index.php.skeleton`; credentials come from the addon settings (`addon_configs.json`, editable in the Tools UI) with a fallback to `.env.local` (`CHAT_USERNAME`/`CHAT_PASSWORD`, `APP_SHELL_*`, `ROOT_SHELL_*`). Protection is active only when both username and password are present and non-empty.
  Addons opt in via the routing flag `"auth": "cookie"` - the chat addon uses it, so the chat service itself stays credential-free at the proxy layer.
  The Tools UI keeps its HTTP Basic Auth, and in ports routing mode the shells keep the `ttyd` login dialog.

- **Addon Dependency Mount Propagation**
  `updateDockerOverride()` in the tools UI previously wrote every tool mount into the `web` service only, so addon services depending on a mount-carrying tool (chat → OpenCode CLI) silently missed the new state mount.
  Tools mounts are now also propagated to the compose services of installed addons that declare the tool in their `dependencies` list, keeping addon-specific mounts out of unrelated services.

- **Chat Model Selection Labels**
  The chat model dropdown now shows the provider in parentheses for every entry (`Model (Provider)`, provider default `Model (Provider, default)`), so models with identical display names stay distinguishable across providers.
  The bundled chat documentation describes the label format and the default marking accordingly.

- **Version Bump and Documentation**
  `src/Cli.php` was bumped to 1.0.6, and `README.md` as well as `readme/README.de.md` were updated to reflect the 1.0.6 release; `doc/rls/1.0.6.md` was added.

**Compatibility**: Backward compatible for the stack in general. In paths routing mode the shells and the chat now use the form login - newly generated projects include the `vibe-auth` endpoint out of the box, existing projects pick it up together with the new proxy configuration when the project is regenerated; ports routing mode keeps the previous `ttyd` login dialogs. Chat credentials are read from the addon settings or `.env.local`; after changing `CHAT_*` run `docker compose restart tools web`. Tool mounts reach dependent addon services with the next regeneration of `docker-compose.override.yml` (any tools UI action).
