# Release 1.0.5 - Changelog Summary

This release reworks the model selection of the Chat addon so that the browser chat mirrors the OpenCode TUI: favorites always win, recent models are the fallback, and OpenCode Zen is the starting point for fresh projects. Favorites and recent models are now stored in a shared state directory, so a model starred in the terminal shell is immediately available in the chat UI.

- **Model Selection Cascade (Chat Addon)**
  The chat model dropdown now follows a strict three-tier cascade instead of listing every provider model:
  1. **Favorites** - if `favorite` entries exist in OpenCode's model state, only those are offered.
  2. **Recent** - without favorites, only the recently used models are offered.
  3. **OpenCode Zen** - with an empty state, only the bundled OpenCode Zen (`opencode`) models are offered, so new projects start with a working free model set instead of an overwhelming provider list.
  Entries are validated against `/config/providers`; stale favorites or recents pointing to unknown models are dropped and the next tier applies.

- **Shared OpenCode State Directory**
  OpenCode stores UI state (favorites, recent models, variants) in `~/.local/state/opencode/model.json` (XDG state), not in the data directory.
  The generated stack now mounts `./docker/web/settings/opencode-state:/home/application/.local/state/opencode` into both the `web` and `chat` services, so models starred in the OpenCode TUI inside the application shell are instantly visible in the chat model dropdown (and vice versa).
  The OpenCode CLI tool definition (`170_opencode.json.skeleton`) carries the additional mount for new and re-synced projects.

- **Chat models.json Endpoint Fix**
  The chat nginx config now serves `/models.json` from the shared state path (`~/.local/state/opencode/model.json`) instead of the data directory, where OpenCode 1.18 never writes the file.
  The chat `start.sh` creates the state directory up front.

- **Addon Dependency Mount Propagation**
  `updateDockerOverride()` in the tools UI previously wrote every tool mount into the `web` service only, so addon services depending on a mount-carrying tool (chat → OpenCode CLI) silently missed the new state mount.
  Tools mounts are now also propagated to the compose services of installed addons that declare the tool in their `dependencies` list, keeping addon-specific mounts out of unrelated services.

- **Version Bump and Documentation**
  `src/Cli.php`, `README.md`, and `readme/README.de.md` were updated to reflect the 1.0.5 release, and `doc/rls/1.0.5.md` was added.

**Compatibility**: Backward compatible for the stack in general. Existing chat installations need the new `opencode-state` mount: re-run the OpenCode CLI tool installation (or any tools UI action that regenerates `docker-compose.override.yml`) and the mount is written into `web` and `chat` automatically; until then the chat falls back to the OpenCode Zen model list.
