# Release 1.0.8 - Changelog Summary

This release upgrades the Chat and Veronica addons to a shared, current feature level: i18n, plan mode, a model menu with self-healing selections, visible provider errors, PWA assets - and Veronica's accounts move from per-browser storage to a server-side user database.

- **Veronica: Server-Side User Database**
  Accounts previously lived in each browser's `localStorage` (with a config-based bootstrap seed). They now live in a server-side JSON database (`/data/veronica-users.json` inside the container, mounted at `docker/web/settings/veronica` on the host): logins survive container rebuilds and work across browsers and devices. The database is served by a built-in php-fpm endpoint (`/api/users`, now part of the addon Dockerfile) with atomic writes and a lock file; the UI syncs on load and writes changes back, falling back to `localStorage` only when the API is unreachable. PINs are stored as salted hashes (`sha256:veronica:<alias>:<pin>`).
  *Benefit: real multi-device end-customer deployments - no more per-browser account drift.*

- **Veronica: Bootstrap Seeding Now Server-Side**
  `VERONICA_BOOTSTRAP_ADMIN` + `VERONICA_BOOTSTRAP_ADMIN_PIN_HASH` and `VERONICA_BOOTSTRAP_USERS` are written into the user database on first container start (same environment variables as before). Raw PINs and `sha256:` hashes are both accepted - raw PINs are hashed with the UI's salted scheme so seeded accounts can actually log in.
  *Benefit: the operator seeds accounts once on the host; the accounts exist for every user immediately.*

- **Veronica: Persona Agents (veronica / veronica-plan)**
  The addon container now generates two opencode agents on start: `veronica` (the assistant persona: identity, style, project rules) and `veronica-plan` (read-only plan mode: no file writes, no shell writes, no confirmation prompts - the plan ends with the plan and the Plan toggle in the UI starts implementation). Personas are assembled from multi-file rule folders (`persona/veronica/*.md`, `persona/veronica-plan/*.md` in the opencode config) so deployments can extend them by dropping in additional rule files and restarting.
  *Benefit: end customers get a consistent assistant; plan mode is safe by construction.*

- **Chat & Veronica: Modernized Frontend (i18n, Plan Mode, Model Menu)**
  Both addon frontends were modernized together: UI translations (DE/EN with a language switcher), "stay logged in" (remember-me), a model selection menu with the favorites → recent → recommendations fallback chain, plan-mode toggle in Veronica, markdown rendering shared via `md.js`, PWA assets (manifest, service worker, icons, bundled Inter fonts), and a configurable stuck dialog.
  *Benefit: both chat addons now offer the same, uniform feature set.*

- **Visible Provider Errors + Free-Tier Hint**
  Failed assistant messages render as a red error box instead of disappearing silently (the chat addon previously swallowed them too). OpenCode's free-tier models reject API usage with `403 "OpenCode's free tier can only be used from within OpenCode"` - this case now shows an actionable hint: pick another model in the menu or configure a provider (`OPENCODE_PROVIDER`/`OPENCODE_MODEL` or `opencode auth login`).
  *Benefit: no more silent aborts - end customers see what to do next.*

- **Self-Healing Model Selection**
  A model stored in `localStorage` that the provider list no longer offers (moved deployment, rotated keys) is dropped automatically with a notice; the server's default model takes over instead of failing on every prompt.
  *Benefit: provider config changes no longer brick existing browser sessions.*

- **Addon Skeletons: Source-Based Templates**
  The ~7,700 lines of inline frontend content in `610_chat.json.skeleton` / `620_veronica.json.skeleton` moved to real template files (`docker/tools/addons/{chat,veronica}/templates/www/...` plus the users API under `templates/php/`), referenced via the installer's existing `source` mechanism. All skeleton files now carry the `.skeleton` suffix uniformly - including binary assets (icons, fonts), which pass through the generator's rendering byte-identical.
  *Benefit: the frontend files exist exactly once as regular files in the repository; the addon definitions stay small and readable.*

- **Version Bump and Documentation**
  `src/Cli.php` was bumped to 1.0.8, `README.md` and `readme/README.de.md` were updated (Veronica sections now describe the server-side user database, personas and the new frontend features), and `doc/rls/1.0.8.md` was added.

**Compatibility**: Backward compatible, but Veronica deployments should reinstall the addon in the Tools UI and run `./docker/rebuild.sh` once: the addon image gains php-fpm, and existing browser-stored accounts migrate to the server database automatically on the first UI load (the UI pushes its `localStorage` users to `/api/users` when the server database is still empty). The bootstrap environment variables keep their names and semantics. The new `docker/web/settings/veronica` volume is created automatically.
