# Release 1.0.7 - Changelog Summary

This release introduces the **Veronica** addon (WhatsApp-like end-customer chat in front of a headless OpenCode agent), hardens both chat addons (single-answer questions, visible option descriptions, model selection), and fixes proxy redirects for installations behind port mappings.

- **New Addon: Veronica (End-Customer Chat)**
  WhatsApp-style chat frontend with 2–3 character alias + PIN login (accounts live per browser), conversation list with avatars and unread badges, file uploads (grouped, PDF/images), voice messages, `/`-commands, and per-user OpenCode sessions tagged with `[alias]`.
  End customers only see their own chats; a group can be formed via "add person" - every added member gets their `[alias]` tag appended to the session title, making the group visible in their list. Members can be removed again the same way ("remove person" strips the tag).
  Admins manage users in-app ("manage users": create users, change PIN, promote/demote admins, delete, self-registration toggle - the first registered user automatically becomes admin). A bootstrap mechanism lets deployments pre-seed accounts via environment variables: `VERONICA_BOOTSTRAP_ADMIN` + `VERONICA_BOOTSTRAP_ADMIN_PIN_HASH` (SHA-256 of `veronica:<alias>:<pin>`) and `VERONICA_BOOTSTRAP_USERS` (comma-separated `alias:pinHash`, first entry becomes admin). User list, registration setting and model choice are stored browser-side; no data is kept on the server side of the addon.
  Aliases are 1-3 characters now (single-letter aliases like `v` are valid).

- **Model Selection Menu (Veronica)**
  A dedicated menu (CPU icon, left of the chat menu) lists models with the same fallback chain as the chat addon: favorites (from the OpenCode `model.json` state, exposed via a new `models.json` nginx location) → recent → recommendations (OpenCode Zen, otherwise all models from `/config/providers`). The remaining models are always offered below favorites/recent so switching is always possible.
  The active model is marked bold; the choice is sent with every prompt (`providerID`/`modelID`) and stored per browser.

- **Group Chat Fixes (Veronica)**
  Adding a member now passes the full session object to the rename path, so the `[alias]` title tag is reliably appended (previously the rename silently never ran and added members never saw the group).
  Session visibility filter matches both owner prefix and member tags; member lists and display titles are derived from the title tags (all `[alias]` tags stripped for display).

- **Chat & Veronica Questions**
  Only one answer may be selected per question (previously multi-select plus free text stacked). Option descriptions are now rendered visibly under the option label instead of a tooltip, in both the chat modal and Veronica's inline question flow.

- **Sidebar Toggles (Veronica)**
  A toggle in the sidebar header (right of the admin button) collapses the sidebar; when collapsed, a topbar toggle appears - on the left on desktop, on the right on mobile - only in that state. Both sized to align with the topbar line (69px).

- **Robustness**
  `detectBackend()` retries (3× 1s) before falling back to mock mode, so container restarts no longer trap the UI in mock mode.
  The chat login redirect chain is fixed for mapped ports: the proxy now uses `absolute_redirect off`, so form-login redirects stay relative and land on the correct host/port.

- **Version Bump and Documentation**
  `src/Cli.php` was bumped to 1.0.7, and `README.md` as well as `readme/README.de.md` were updated to reflect the 1.0.7 release; `doc/rls/1.0.7.md` was added.

**Compatibility**: Backward compatible. Existing projects pick up the updated addon definitions on the next (re)installation of chat/veronica in the Tools UI; Veronica deployments configure accounts via the addon config (Basic Auth, allow-registration) and optionally the bootstrap environment variables. Favorites/recent markers come from the shared OpenCode state and appear identically in the chat addon and Veronica.
