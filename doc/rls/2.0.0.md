# Release 2.0.0 - OpenCode v2 in the AI addons

This release moves all three AI addons (**opencode**, **Chat**, **Veronica**) from OpenCode 1.x to **OpenCode v2** and brings the v2-powered feature set to both web UIs. OpenCode 2 intentionally changes its server API, so the Chat and Veronica apps were ported to the new contracts - the addon templates now carry the same feature level as the `vibe4dock-arcvd` image.

- **OpenCode v2 + transparent API auth**
  The addon Dockerfiles install OpenCode from the v2 installer channel (`opencode.ai/v2/install`). v2 protects its server API with HTTP Basic auth and generates a new password on every start. The Chat/Veronica start scripts extract it from the server log and inject it as an `Authorization` header into the nginx `/api/` route, so the browser UIs work unchanged. The standalone opencode addon switches from the removed `opencode web` command to `opencode serve` (API + web UI); its web UI asks once for the server password, which is printed to the container log and written to `.opencode-password` in the project.
  *Benefit: current agent runtime without weakening the addon UX.*

- **Live updates instead of fixed polling**
  Both UIs subscribe to the v2 event stream (`/api/event`) and refresh within ~250 ms of a server event; the 1.5 s poll remains as fallback. nginx uses `flushpackets=on`/`proxy_buffering off` so the stream passes through.
  *Benefit: answers and tool activity appear in near-realtime.*

- **Message steering while generating**
  Messages sent during a running generation steer the current run (v2 delivery semantics) instead of being queued client-side or blocked. The Chat keeps commands parked until idle; Veronica steers in API mode and keeps its queue for mock mode.
  *Benefit: follow-up thoughts reach the agent immediately.*

- **Richer session context**
  Both sidebars show per-session cost/token usage and outcome icons (succeeded/failed/interrupted) from the v2 session records. The Chat adds session fork (`/session/{id}/fork`), compact (`/session/{id}/compact`) and a per-session diff viewer (`/session/{id}/diff`, files with patches and +/- counts).
  *Benefit: sessions are manageable and transparent without touching a terminal.*

- **Better questions, permissions and model picks**
  Agent questions render as structured v2 forms - including multi-select answers with free text ("Apply" submits the set). Permission requests are decoded from the v2 payload (action, resources, metadata and the referenced tool call) and now name the exact command or path instead of a generic label. The Veronica model menu gains reasoning-mode variants per model (persisted, sent as `Model.Ref.variant`), and Veronica's chat menu adds an "undo last change" action (`DELETE /session/{id}/revert`).
  *Benefit: users see what is being asked, approved and selected.*

**Compatibility:** existing projects keep their sessions (v2 migrates the SQLite database in place on first start). The addon templates ship the updated UI assets; rebuild the stack (`./docker/rebuild.sh`) after updating the tool so the new image and assets are generated. Provider credentials configured via `OPENCODE_API_KEY` keep working (v2 reads them as environment connections); credentials from a legacy `auth.json` are imported once when the v2 database is still empty.
